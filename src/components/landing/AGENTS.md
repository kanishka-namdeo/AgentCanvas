# AGENTS.md — `src/components/landing/`

## Purpose

Everything behind the marketing landing page (route `/`, landing-page plan 2026-09-13): the shared primitives (repo-url constants, SmoothScroll, BrowserFrame, video-playback) plus the seven-section set — Hero, MagicSequence, FeatureGallery, TrustLoop, SocialProof, HowItWorks, OpenSourceFinale — composed by `src/app/page.tsx` → `LandingTree` and framed by `LandingHeader` / `LandingFooter`. The workspace app itself lives at `/app` (`src/app/app/page.tsx`) and must not import from here.

## Ownership

- `repo-url.ts` — `REPO_URL` / `REPO_CLONE_URL`, the ONLY place the repo URL literal appears. Everything (header Star link, footer GitHub link, clone command, JSON-LD, GitHub API fetch) imports from here; never re-type the URL. Canonical name is `AgentCanvas` (git remote is ground truth; the old `co-canvas` URL 301s here). `SITE_URL` is the absolute metadata base (canonical / og:url / sitemap), overridable via `NEXT_PUBLIC_SITE_URL`; it defaults to the sandbox preview host users actually see.
- `SmoothScroll.tsx` — `'use client'` lenis provider (landing-page plan Task 8), mounted by `src/app/page.tsx` around the whole landing. Under `prefers-reduced-motion` (via `useReducedMotion()`) it renders children bare so anchor links fall back to native scrolling (LandingHeader's `useLenis()` returns `null`); otherwise `<ReactLenis root options={{ lerp: 0.1, smoothWheel: true }}>` with `'lenis/dist/lenis.css'`. Test note: vitest aliases `lenis/dist/lenis.css` to `tests/stubs/empty-module.ts` — a real CSS import would drag the Next/Tailwind PostCSS config into the vitest transform pipeline, which fails there (see `vitest.config.ts`).
- `BrowserFrame.tsx` — light-chrome browser mockup (`data-testid="browser-frame"`): traffic-light chrome bar + fixed-aspect viewport (default `16 / 10`). All landing screenshots are LIGHT-mode captures on a DARK page, so they are always framed inside this light chrome — never pasted raw. `crop="bottom"` overlays a light fade over the viewport's bottom edge (spec §6: screenshot artifacts are cropped in CSS, never edited out of the source PNGs); pair with `object-cover object-top` on the child image and a NARROWER `aspectRatio` than the source shot.
- `LandingHeader.tsx` — `'use client'` FIXED header over the whole page (2026-09-19 uplift): transparent over the hero, then a blurred dark surface + hairline border once `scrollY > 0.6 × innerHeight` (`data-scrolled`, plain window listener so it also works under reduced motion). Exports `LANDING_SECTIONS`, the single source of the five below-hero anchor ids (`magic`, `tool`, `trust`, `how-it-works`, `open-source`) — section components MUST render elements with these ids. Anchor clicks scroll via `lenis` (`useLenis`) with NO manual offset — sections own their breathing room through `scroll-mt-20` (the old `offset: -72` double-compensated and landed links 152px low); without a provider (prefers-reduced-motion) `useLenis()` returns `null` and clicks fall through to native anchor scrolling, which resolves the same `scroll-mt-20`. CTAs: `header-star` → `REPO_URL` (label is `Star` unless `hasStars`), `header-open` → `/app` (`.ac-brand-gradient` pill).
- `MagicSequence.tsx` — the Magic section (spec §5.2; rebuilt 2026-09-19): `<section id="magic" data-testid="section-magic">`, heading "Describe it. Watch it appear.", a 250vh scroll track (`md:h-[250vh]`) whose sticky grid (`md:sticky md:top-24`) pins while `useScroll` progress crossfades THREE absolutely-stacked layers — `magic-frame-build` (hero-build.png) → `magic-frame-work` (`AgentTimeline` mock) → `magic-frame-done` (dashboard-complete.png) — with `useMotionValueEvent` highlighting the active step card (`data-active`). The old ~470px grid made progress degenerate (dashboard peaked at 0.26 opacity, never completed); the 250vh track is the fix. Step 01 types its prompt (`magic-typing`, reduced-motion static `magic-typing-static`); step 02 carries the task list. Reduced-motion branch: ONE static dashboard frame (`magic-final-static`), no scroll transforms, static prompt, no pinning. Frame is `4 / 3` + `crop="bottom"`; images use `object-cover object-top` so the dashboard shot's bottom edge (the "202 Issues" toast) crops out in CSS (spec §6).
- `FeatureGallery.tsx` — the Feature section (spec §5.3): `<section id="tool" data-testid="section-tool">`, heading "Not a toy — a Figma-grade tool.", a THREE-column `BentoGrid` of FIVE `BentoCard`s (Figma-grade tooling / One-shot generators / Design systems built in / .pen file format / Sessions & snapshots — every one with a visible icon, real copy, and an ALWAYS-visible CTA "Open the canvas" href `/app`; the pre-uplift hover-revealed CTAs made cards read as empty black boxes), a `gallery-motion-row` 2-up (md:grid-cols-2, gap-6) between the grid and the band — two 16/10 `BrowserFrame`s carrying `tooling-tour.mp4` (`gallery-video-tooling`) and `design-pack.mp4` (`gallery-video-design-pack`), each `preload="none"` + poster + a real `<p>` caption (`gallery-caption-<id>`, `text-sm text-white/50` + lucide icon) that carries the meaning because the clips are decorative (`aria-hidden`, `tabIndex={-1}`); ONE `useInView` on the row container drives both (they pause together when the row leaves) — and a full-width parallax band: `attention-heatmap.png` (1280×577) in a `BrowserFrame` (`aspectRatio="16 / 7"` + `crop="bottom"`, `object-cover object-top` so the bottom-edge toast artifact crops out in CSS per spec §6) with `useScroll` + `useTransform` y parallax (±32px). Reduced-motion branch: parallax transform omitted, the motion row renders its poster stills via `next/image` (`gallery-poster-<id>`) instead of any `<video>` (no autoplay anywhere), all copy/images still render.
- `video-playback.ts` — `setVideoPlaying(video, play)`, the ONE play/pause driver for the landing's decorative videos (Hero + FeatureGallery call sites). Callers own visibility (motion `useInView`); this owns the element: resume only when paused, pause when not, swallow autoplay rejections, and gate on `canPlayType('video/mp4')` — jsdom (unit tests) answers `''`, so the media calls are skipped and tests stay free of jsdom "not implemented" errors.
- `GitHubStars.tsx` — the GitHub proof layer (2026-09-19 uplift). `fetchGitHubStats()` is the server half: ONE GET to `api.github.com/repos/<owner>/<repo>` parsed from `REPO_URL`, `next: { revalidate: 3600 }`, returning `null` on ANY failure (network, rate limit, bad payload) — never a fabricated count. `hasStars(stars)` / `formatStarCount()` / `<GitHubStars>` are the presentational half. ZERO-SUPPRESSION RULE: `hasStars` is true only for a number > 0, and `GitHubStars` renders NOTHING otherwise — `★ 0` is anti-proof, so a fresh repo shows the rest of the proof row (AGPL-3.0 · 60+ tools · 28 providers) and omits the count. Consumers gate star segments on `hasStars` (Hero proof row, LandingHeader chip label, OpenSourceFinale CTA).
- `SocialProof.tsx` — the honest proof band: a "Built on" tech marquee (real `package.json` deps; the looping copies are `aria-hidden` with one `sr-only` list) plus stat tiles where EVERY GitHub tile is gated on a value > 0 (a `★ 0` / `0 forks` wall is anti-proof) — a fresh repo degrades to the AGPL-3.0 license tile + marquee. Server-safe, no hooks, deliberately NOT an anchor section (no id, not in `LANDING_SECTIONS`). Nothing here may be fabricated: no testimonials, no customer logos.
- `AgentTimeline.tsx` — the Magic sequence's "02 — agent working" layer: a pure-DOM `motion` mock of the product's agent panel (tool-call rows stagger in and the feed remounts every ~6s cycle; a `mt-auto` composer strip using the product's own placeholder copy fills the frame's lower third). Light surface inside the light-chrome frame; no video. Under `prefers-reduced-motion` it renders the completed list statically (no interval, no pulse).
- `LandingTree.tsx` — the composed section tree inside the SmoothScroll boundary. Contract: `statsPromise` crosses the server/client boundary, so on the client it is a React STREAMED THENABLE whose `then()` returns `undefined` — never chain `.catch()` onto it (that threw a page-killing TypeError; caught 2026-09-19). `Promise.resolve(promise)` adopts it into a real promise first; the resolved stats land in state via effect (NOT `use()` — React 19's `use()` never retried the suspended boundary under this repo's vitest/jsdom renderer, so the tree stayed stuck on the fallback in unit tests). A `null` resolution drops every star segment (GitHubStars).
- `TrustLoop.tsx` — the Trust section (spec §5.4): `<section id="trust" data-testid="section-trust">`, heading "You approve. No scroll motion, and no video: no current-UI approval footage exists (capture-selection.md records the gap), so the still is the honest asset.
- `HowItWorks.tsx` — the developer-depth section (spec §5.5): `<section id="how-it-works" data-testid="section-how-it-works">`, heading "How it works", a pure CSS/flex diagram (Prompt → Agent → Tools → Canvas boxes, `flow-prompt`/`flow-agent`/`flow-tools`/`flow-canvas` testids, Geist Mono labels via `[font-family:var(--font-geist-mono),monospace]`, `ArrowRight` connectors that rotate 90° on mobile) — no images, ever. ## Local Contracts

- Dark landing, light screenshots: the light-chrome BrowserFrame contract above is not optional.
- Header anchors and section ids both derive from `LANDING_SECTIONS` — a new below-hero section is added there AND rendered with the matching id by its section component.
- Components here are landing-only; shared app chrome stays out (root `src/components/AGENTS.md` owns ThemeToggle/ErrorBoundary).
- **Proof is never fabricated (2026-09-19)**: every number on this page comes from a real source — `fetchGitHubStats` for GitHub counts, `package.json` for the tech marquee, the repo for tool/provider counts — and any value that would read as a zero/unknown is DROPPED, not printed (`hasStars`; SocialProof's `> 0` tile gates). A failed fetch degrades to the copy-only proof row; it never falls back to a hardcoded count.
- **Video assets (2026-09-19)**: `public/landing/` serves three verified cuts under stable names — `build-reveal.mp4` + `build-reveal-poster.png` (Hero), `tooling-tour.mp4`/`-poster.png` and `design-pack.mp4`/`-poster.png` (FeatureGallery). All 1600×1000 (exactly the frames' default 16/10 viewport → zero crop) except `design-pack.mp4`, which is re-encoded to 1280×800 CRF 24 (tile weight ≤700 KB). `smoke-canvas.mp4` stays unused in `download/landing-uplift/selected/`; the legacy `core-agent-chat.mp4` / `core-trust-loop.mp4` b-roll is deleted and `tests/unit/landing-assets.test.ts` guards both facts plus the byte budgets. Provenance + trim rationale: `download/landing-uplift/capture-selection.md`.
- **Video playback contract**: every decorative clip is `muted loop playsInline aria-hidden tabIndex={-1}` and decodes only while on screen (`useInView` → `setVideoPlaying`). Under `prefers-reduced-motion` NO `<video>` is rendered at all — the static screenshot/poster is the fallback (and the no-JS visual). Autoplay is Hero-only; the gallery clips are `preload="none"` and start on in-view.
