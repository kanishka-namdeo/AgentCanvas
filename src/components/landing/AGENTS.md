# AGENTS.md — `src/components/landing/`

## Purpose

Everything behind the marketing landing page (route `/`, landing-page plan 2026-09-13): the shared primitives (repo-url constants, SmoothScroll, BrowserFrame, video-playback) plus the seven-section set — Hero, MagicSequence, FeatureGallery, TrustLoop, SocialProof, HowItWorks, OpenSourceFinale — composed by `src/app/page.tsx` → `LandingTree` and framed by `LandingHeader` / `LandingFooter`. The workspace app itself lives at `/app` (`src/app/app/page.tsx`) and must not import from here.

## Ownership

- `repo-url.ts` — `REPO_URL` / `REPO_CLONE_URL`, the ONLY place the repo URL literal appears. Everything (header Star link, footer GitHub link, clone command, JSON-LD, GitHub API fetch) imports from here; never re-type the URL. Canonical name is `AgentCanvas` (git remote is ground truth; the old `co-canvas` URL 301s here). `SITE_URL` is the absolute metadata base (canonical / og:url / sitemap), overridable via `NEXT_PUBLIC_SITE_URL`; it defaults to the sandbox preview host users actually see.
- `SmoothScroll.tsx` — `'use client'` lenis provider (landing-page plan Task 8), mounted by `src/app/page.tsx` around the whole landing. Under `prefers-reduced-motion` (via `useReducedMotion()`) it renders children bare so anchor links fall back to native scrolling (LandingHeader's `useLenis()` returns `null`); otherwise `<ReactLenis root options={{ lerp: 0.1, smoothWheel: true }}>` with `'lenis/dist/lenis.css'`. Test note: vitest aliases `lenis/dist/lenis.css` to `tests/stubs/empty-module.ts` — a real CSS import would drag the Next/Tailwind PostCSS config into the vitest transform pipeline, which fails there (see `vitest.config.ts`).
- `BrowserFrame.tsx` — light-chrome browser mockup (`data-testid="browser-frame"`): traffic-light chrome bar + fixed-aspect viewport (default `16 / 10`). All landing screenshots are LIGHT-mode captures on a DARK page, so they are always framed inside this light chrome — never pasted raw. `crop="bottom"` overlays a light fade over the viewport's bottom edge (spec §6: screenshot artifacts are cropped in CSS, never edited out of the source PNGs); pair with `object-cover object-top` on the child image and a NARROWER `aspectRatio` than the source shot.
- `LandingHeader.tsx` — `'use client'` FIXED header over the whole page (2026-09-19 uplift): transparent over the hero, then a blurred dark surface + hairline border once `scrollY > 0.6 × innerHeight` (`data-scrolled`, plain window listener so it also works under reduced motion). Exports `LANDING_SECTIONS`, the single source of the five below-hero anchor ids (`magic`, `tool`, `trust`, `how-it-works`, `open-source`) — section components MUST render elements with these ids. Anchor clicks scroll via `lenis` (`useLenis`) with NO manual offset — sections own their breathing room through `scroll-mt-20` (the old `offset: -72` double-compensated and landed links 152px low); without a provider (prefers-reduced-motion) `useLenis()` returns `null` and clicks fall through to native anchor scrolling, which resolves the same `scroll-mt-20`. - `ScrollCanvasInteractions.tsx` — the keyboard + mouse interaction layer for `ScrollCanvas` (landing-interactions task). Exposes `useScrollCanvasKeyboard()` returning `{ sectionRef, isPlaying, currentStep, totalSteps, examplePrompts, currentExampleIndex }` (no args — the hook finds its own track via `sectionRef.current.querySelector('[data-testid="scroll-canvas-track"]')`). The hook attaches a `keydown` listener to the section via `addEventListener` (not React's `onKeyDown`) so it sees events bubbling from descendant focusable elements too. Shortcuts implemented: `Space` toggles autoplay (RAF loop advances scroll progress ~0.5% per frame until the track completes, then auto-stops); `Enter` + `→` advance one step (scroll to the next `STEP_THRESHOLDS` boundary); `←` reverses one step; `↑`/`↓` cycle `currentExampleIndex` through `EXAMPLE_PROMPTS` (purely visual — no scroll); `Esc` resets to step 0 (scroll to the start of the track); `Tab` is native (not intercepted). Inputs/textareas/contentEditable hosts are skipped (Space/Enter/arrows there belong to the field). Click-to-scroll: a separate `useEffect` attaches a `click` listener to the section that scrolls to the next `<section>` sibling via `scrollIntoView`, ignoring clicks inside the prompt chip. Reduced-motion contract: every shortcut that drives scroll (Space, Enter, ←/→, Esc) AND the example cycling (↑/↓) bail out when `useReducedMotion()` returns true — the canvas is already at its final state, so there's nothing to scrub or cycle toward. `getProgress` returns 1 under reduced motion (completed), 0 when the track is unmeasured (jsdom's `getBoundingClientRect` returns 0 height — without this guard, `total <= 0` would divide-by-zero into NaN that lifts `currentStep` to its ceiling and breaks the "Step 01 / 11" initial-render assertion), and the real `-rect.top / total` otherwise. Exports `EXAMPLE_PROMPTS` (4 strings, starting with the canonical `'Build a dashboard with 3 stat cards'`), `TOTAL_STEPS` (11, matches ScrollCanvas's `STATUS_TEXTS.length - 1`), and the `scrollToNextSection(section, reduced)` helper used by both the hook's click handler and `ScrollCanvas`'s "Scroll to explore ↓" hint button (ONE owner for the next-sibling lookup).

## Local Contracts

- Dark landing, light screenshots: the light-chrome BrowserFrame contract above is not optional.
- Header anchors and section ids both derive from `LANDING_SECTIONS` — a new below-hero section is added there AND rendered with the matching id by its section component.
- Components here are landing-only; shared app chrome stays out (root `src/components/AGENTS.md` owns ThemeToggle/ErrorBoundary).
- **Proof is never fabricated (2026-09-19)**: every number on this page comes from a real source — `fetchGitHubStats` for GitHub counts, `package.json` for the tech marquee, the repo for tool/provider counts — and any value that would read as a zero/unknown is DROPPED, not printed (`hasStars`; SocialProof's `> 0` tile gates). A failed fetch degrades to the copy-only proof row; it never falls back to a hardcoded count.
- **Video assets (2026-09-19)**: `public/landing/` serves three verified cuts under stable names — `build-reveal.mp4` + `build-reveal-poster.png` (Hero), `tooling-tour.mp4`/`-poster.png` and `design-pack.mp4`/`-poster.png` (FeatureGallery). All 1600×1000 (exactly the frames' default 16/10 viewport → zero crop) except `design-pack.mp4`, which is re-encoded to 1280×800 CRF 24 (tile weight ≤700 KB). `smoke-canvas.mp4` stays unused in `download/landing-uplift/selected/`; the legacy `core-agent-chat.mp4` / `core-trust-loop.mp4` b-roll is deleted and `tests/unit/landing-assets.test.ts` guards both facts plus the byte budgets. Provenance + trim rationale: `download/landing-uplift/capture-selection.md`.
- **Video playback contract**: every decorative clip is `muted loop playsInline aria-hidden tabIndex={-1}` and decodes only while on screen (`useInView` → `setVideoPlaying`). Under `prefers-reduced-motion` NO `<video>` is rendered at all — the static screenshot/poster is the fallback (and the no-JS visual). Autoplay is Hero-only; the gallery clips are `preload="none"` and start on in-view.

## Scrollytelling architecture notes (landing-scrollytelling task)

- **Lenis ↔ Framer Motion `useScroll` compatibility** (documented in `SmoothScroll.tsx`'s header comment): Lenis does NOT replace the native scroll position — it interpolates the TARGET scroll position in a `requestAnimationFrame` loop and writes back to `window.scrollY`, so `useScroll({ target })` (whose default source is the native `window` scroll) sees the same interpolated values Lenis renders. ScrollCanvas's scrub stays 1:1 with what's on screen — there is no double-buffering conflict. Lenis only changes scroll *velocity* (smooths fast scrolls) and wheel-event prevention (never lets the page overshoot the interpolated target); neither affects the read-only `useScroll`. If a future feature needs Lenis's own `on('scroll', cb)` callback, `useLenis()` is available — no landing component currently needs it.
- **SVG draw-on technique**: each `<motion.rect>` carries `strokeDasharray={perimeter}` (perimeter = `2*(w+h)`) + a `style.strokeDashoffset` MotionValue that animates `perimeter → 0` over its draw-step range. Fills fade in on the SAME rect via a separate `style.fillOpacity` MotionValue. SVG paint order keeps the stroke rendered ON TOP of the fill once both are visible. Chart bars grow via `scaleY` 0→1 with `transform-box: 'fill-box'` + `transform-origin: '50% 100%'` so the bar's bottom stays anchored to the chart baseline (otherwise the bar would grow from its center, not its base — visually wrong for a chart).
- **Mouse parallax spring**: `useSpring(rotateYMV, { stiffness: 120, damping: 18 })` are Framer Motion defaults and match the research report §C.1 spec. Cap the raw MotionValue at `±6°` (so the spring settles at `±3°` after damping); `±4°` raw for rotateX settles at `±2°`. The spring is OFF under reduced motion (`style={undefined}` on the motion.div, `pointermove` is a no-op).
- **Reduced-motion collapsed track**: the `md:h-[300vh]` track is omitted entirely (the className is conditional on `reduced`), so a reduced-motion user scrolling past the section doesn't traverse 3 viewport-heights of empty pinned space — they see the completed dashboard in one viewport and scroll on to MagicSequence.
